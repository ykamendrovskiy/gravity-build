# Каталог решений сервиса — формат

Каталог — папка `catalog/` в корне целевого проекта (рядом с `service-profile.json`): **индекс того, что на
сайте уже есть и где лежит код**. Код первичен; каталог указывает. Его читает сборка (`create`) перед новой
страницей; сборка же добавляет карточку того, что построила. Опыт (грабли, причины отказов) в каталог не
пишется: то, что уже учтено в коде, следующий сборщик получает, копируя код.

## Папка

```
catalog/
  index.md      генерируется скриптом из карточек: одна строка на единицу. Это читает create целиком.
  <id>.md       карточка единицы: та же строка + код + раздел + ссылки (гайд registry, отчёт сборки).
```

- **Наполнение:** бутстрап скриптом из репо (карточки основного списка; человек уточняет фразы) и сборка
  (create добавляет карточку построенной страницы/единицы).
- **Изменение:** карточка — файл; правится руками или репликой скиллу; индекс всегда пересобирается
  (`extract-catalog.mjs --index catalog/`). Репо ушёл вперёд — режим обновления скилла `catalog`.
- **Удаление:** удалил `catalog/<id>.md` → `--index`. Или «убери X» скиллу.
- **Дрейф:** карточка, чей код в дереве не найден, помечается линтом (`--lint catalog/`).

## Строка индекса

```
- **<id>** — `<маршрут>` · <одна фраза: что это / для какой задачи> · код: `<файл, файл>`
```

- **id** — kebab-case с префиксом раздела (`archetype-…`, `block-…`, `component-…`, `data-…`, `conv-…`).
- **фраза** — задача, которую единица решает («каталог сущностей с поиском и карточками»), не пересказ
  компонента; цель или факт, не способ.
- **код** — 1–3 файла или папки, по которым единицу можно открыть и повторить.

## Карточка `<id>.md`

```
# <id>
<та же строка индекса>
код: <файл>, <файл>
раздел: <Страницы | Каркас | Блоки | Компоненты | Модели контента | Источники данных | Как принято | Вне каталога>
ссылки: <гайд registry / отчёт сборки / AUDIT — по желанию>
```

## Разделы индекса

Страницы (по устройству) · Каркас · Блоки · Компоненты · Модели контента и данные · Источники данных
(в строке — ограничения: кэш, токен, покрытие) · Как принято в репо (правило одной фразой + пример-файл) ·
Вне каталога, но существует (одна строка с причиной: своя механика, legacy).

## Правила

- **Не индексировать всё.** Каталогизируется то, что иначе переизобретут: архетипы страниц, повторяемые
  блоки, источники данных, конвенции. 40–60 строк индекса на сайт среднего размера — норма.
- **Строка остаётся строкой** (линт: > 200 знаков текста без пути к коду — предупреждение).
- **Запись — в том дереве, где код.** Карточка о единице из другого дерева несёт пометку «где живёт».
- **Опыт — не сюда.** Грабля, на которую наступили, живёт как фикс в коде, как инвариант гейта или как
  пример в registry; незакрытый дефект — в «Что дальше» отчёта сборки и бэклог проекта.

## Как каталогом пользуются скиллы

- **create:** прочитать `catalog/index.md`; карточки — только выбранных единиц; сверься — что уже есть и
  как устроено; не изобретай новое без необходимости; если существующее не подходит — скажи почему (в
  отчёте, коротко). Построил новую страницу/единицу — **добавь её карточку** и пересобери индекс.
- **catalog:** бутстрап (скрипт → папка), обновление при изменении репо, разбор по просьбе.

Пример — папка `catalog.example/` рядом.
