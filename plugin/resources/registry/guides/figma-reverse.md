# figma-reverse — перенос сборки в Figma-макет на компонентах кита (обратный перенос)

> Тип: route-guide, семейство source-out. Открывай, когда **выход сборки — Figma-макет**: «положи прототип в Figma»,
> «собери макет из кода», «дизайнеру нужен макет на ките», «обнови макет по коду». Ссылка на целевой Figma-файл сама
> по себе **не** входной макет — шаги scaffold/build/verify прямой цепочки здесь не применяются. Направление истины:
> **код = ЧТО показать** (тексты verbatim, раскладка, состояния, токены темы), **кит = ИЗ ЧЕГО собрать**. Это
> экспозиция устройства и связей, не пошаговая инструкция: решения по ходу — твои, стоп-правило — две итерации на
> расхождение, дальше класс в отчёт. Контракт канала записи (страница сбрасывается между вызовами, восстановление
> после ошибки, лимиты поиска) — в актуальном Figma-скилле среды, здесь не дублируется.
> verified 2026-09-06: шесть сборок (почтовик / трекер / сценарий ×5 на локальной копии кита и на опубликованной
> «YC Gravity UI»), два наивных прогона по гайду, независимое ревью и живой прогон второго ревьюера.

## Как читать этот файл

- **кит** — Figma-библиотека компонентов: *опубликованная* (идентифицируется `libraryKey`, компоненты/стили/переменные
  импортируются по ключам) или *локальная копия* (идентифицируется `fileKey` + id компонентов в самом файле). Иконки и
  иллюстрации обычно — отдельные библиотеки со своими ключами. Ищи всегда со скоупом библиотеки.
- **сет / вариант / проп** — `COMPONENT_SET` = компонент кода; ось варианта (`View=Action, Size=L`) = enum-проп;
  свойства инстанса (`TEXT`, `BOOLEAN`, `INSTANCE_SWAP`) = остальные пропы. Ключи свойств несут суффикс `#id` —
  ищи по нормализованному имени (`trim`), проверяй единственность совпадения и тип свойства; **ключи не набирай
  руками** — резолви из определений (там встречаются кириллические буквы в латинских словах: `↳ Сounter`).
- **паспорт кита** — кэш на библиотеку: ключи сетов/иконок, определения свойств, словарь токенов, шрифт, грабли —
  с датой снятия и происхождением. Перед повторным использованием сверяются нужные ключи и определения:
  библиотека меняется при том же `libraryKey`.
- **раунд-трип** — если код был собран из макета, сравнение «макет → код → макет′» по инстансам (сет · вариант ·
  свойства · свап · тексты). Дополнительная проверка, не замена сверки с кодом: сигнатуры могут совпасть при другой
  картинке, заливке и геометрии.

## Кит и код: что чему соответствует

| В коде (Gravity UI) | В ките (Figma) | Как задаётся |
|---|---|---|
| компонент `Button`, `TextInput`… | `COMPONENT_SET` с тем же именем (иногда с пробелом/суффиксом: `User `, `List-item`) | вариант по имени → `createInstance()`; `defaultVariant` — только заготовка: заданные кодом оси применяются и проверяются, отсутствующая комбинация → `unresolved`, не «hit» |
| enum-проп `view` / `size` / `theme` | ось варианта `View` / `Size` / `Theme` | часть имени варианта |
| `checked`, `disabled`, `selected` | булевоподобные оси названы по-разному (`Checked=On/Off`, `Selected=True/False`, `State=Disabled`) | читай варианты сета, не угадывай |
| `children`-текст, `label`, `placeholder` | `TEXT`-свойство (`Content#…`, `↳ Label text#…`) **или** вложенный `TEXT`-узел без свойства | `setProperties` / `characters`; учитывай текущие шрифты текста **и** шрифт применяемого стиля (`setTextStyleIdAsync` меняет шрифт узла); при `fontName === figma.mixed` — `getRangeAllFontNames` |
| вложенные значения (`Tab counter`, подпись аватара…) | свойства **вложенного** инстанса или вложенный `TEXT` | отсутствие top-level-пропа ≠ отсутствие пары — загляни внутрь до вердикта «нет пары» |
| `placeholder` vs `value` | ось состояния: `State=Suggest` (плейсхолдер) vs `Default` | вариант |
| `startContent`, `Icon data={X}` | `BOOLEAN` «показать слот» **+** `INSTANCE_SWAP` «что в слоте» (бывают два разных булевых) | id компонента иконки, импортированного в файл; ключ храни — id незакреплённых импортов может протухать между вызовами |
| `@gravity-ui/icons` `X` | сет `x-y-z` (kebab-case) в библиотеке иконок, один вариант | `importComponentSetByKeyAsync(key).defaultVariant` |
| `<img>`, аватар по `imgUrl` | IMAGE-fill с исходным ассетом | сначала сам ассет (`createImage(bytes)` / импорт URL, если канал позволяет), захват страницы ради `imageHash` — фолбэк; китовый плейсхолдер = неполный перенос |
| контейнер с `children` (`Card`, `Dialog.Body`) | **SLOT** (принимает `appendChild`) · холдер под свап · ничего | слот: ширина может быть зашита (FILL молчит) → **холдер под свап**: локальный компонент нужной ширины с контентом → `holder.swapComponent(comp)`, тексты override внутри; **подложка**: свой auto-layout с контентом, инстанс кита внутрь `layoutPositioning="ABSOLUTE"` + `constraints STRETCH`, размер под контейнер после того, как контент дал высоту; проверь, что подложка охватывает контент и растёт при удлинении текста; рисующий узел может быть вложенным (`State`), не внешним инстансом |
| `--g-color-*` | **paint-стиль** (в опубликованном ките описание стиля хранит сам токен: `--g-color-text-primary`) или переменная цветовой коллекции | `setFillStyleIdAsync` / `setBoundVariableForPaint` (возвращает новый paint — присвой его обратно в `fills`/`strokes`); **конвенцию снимай с авторских узлов существующего макета**, не с внутренностей инстансов кита |
| `--g-spacing-N`, `--g-border-radius-*` | переменные (`g-spacing-N`, `Border Radius/M radius`) | `setBoundVariable("paddingLeft" …)`; если переменные библиотеки недоступны — числа с пометкой, и метрика хардкода считает геометрию, не только цвета |
| `Text variant="body-1"` | текстовый стиль (`Text/Body 1`, описание «13/18 (text-body-1)») | `setTextStyleIdAsync` |
| тема сервиса (`theme-from-figma.css`, бренд) | **моды коллекции переменных** (у «YC Gravity UI» коллекция `Brand`: YC, YC 2026, Gravity, DataLens…) и/или набор стилей; paint-стили не исключают модов — их paints могут ссылаться на переменные | реальная коллекция и её `modes` — через импортированную переменную → `variableCollectionId` → `getVariableCollectionByIdAsync` (библиотечный дескриптор модов не несёт); мод выставляется на обёртке; какой — вопрос владельцу; несовпадение бренда — явное расхождение темы, не молчаливый фолбэк |
| CSS flex/gap/padding/border | auto-layout: `itemSpacing`, паддинги, `stroke*Weight` по сторонам | вручную по CSS |
| `?scenario=` / состояния манифеста; без манифеста — состояния из `useState`/пропсов корня и веток рендера | фрейм на состояние: **клон базы + дельта состояния** (данные, строки, empty/loading/error, оверлей — если он есть) | 1–4 вызова на состояние против ≈12 у базы; общая ошибка базы чинится по всем клонам |
| библиотека без кит-пары (`markdown-editor`, `ActionTooltip`, бренд-лого, `Button pin`) | нет | аппроксимация раскладкой + строка «нет пары» в отчёте — только после проверки вложенных свойств и слотов |

Ширина внутренних зон в опубликованных китах часто задаётся **осью варианта, а не `resize`** (resize внутри инстанса
молча отвергается); длинный текст в инстансе тоже чинится осью (`Layout=Vertical` / `Multiline`), не FILL; спрятанный
слот не отдаёт высоту. Дефолт вложенной темы контейнера может быть не «Normal» (у `Cards` — `Info`, синяя рамка) —
задавай явно. **Свойства снимай с целевого кита**: локальная копия и опубликованный кит расходятся именами
(`Start icon` ↔ `Start area`, `Item 2…9` ↔ `Item 3…10`). Что проп, а что вложенный узел, дешевле узнать до секции:
определения — с `COMPONENT_SET` (или standalone-`COMPONENT`), значения, видимые тексты и вложенные инстансы — с
временного инстанса, который потом удаляется.

## Откуда брать ключи

- Первый шаг за ключами — **read-only обход того, что уже стоит в целевом файле** (инстансы на его страницах: сеты,
  иконки, стили — обычно закрывает большую часть словаря одним вызовом). Есть исходный макет **на том же ките** → обход
  его инстансов отдаёт ещё и сигнатуру раунд-трипа. Макет на другом ките (локальная копия против опубликованного) даёт только имена и сигнатуру,
  ключи всё равно поиском.
- Нет макета → поиск по дизайн-системе со скоупом библиотеки, по сущностям `component` / `style` / `variable`; лимит
  батча — из ответа канала (в проверенном канале 06.09 — один запрос за вызов). Без скоупа поиск идёт по всем
  библиотекам организации и отдаёт двадцать «Button».
- Дубли имён внутри одного кита (два опубликованных `Cards`) — сравни требуемые свойства и варианты кандидатов; тот,
  чьи инстансы уже в файле, предпочтителен; `updatedAt` — подсказка; выбранный ключ запиши в паспорт.
- Несколько подключённых библиотек с пересекающимися именами → кит-цель фиксируется явно (выбор пользователя или
  профиль сервиса); уже использованный в файле кит и имя пакета кода — подсказки для предложения, не доказательство.
  Роли зависимостей различай: основной UI, иконки, иллюстрации.
- Локальная копия кита: сеты — через `getMainComponentAsync().parent` любого инстанса; локальные компоненты между
  файлами не переносятся.

## Принципы работы (не шаги)

- **Секциями.** Обёртка → колонки/секции по одной за вызов, ≤ ~10 операций; созданные и изменённые узлы возвращай
  **именованной картой id**, не массивом по индексу (позиционные id уводят узлы не туда).
- **Восстановление после ошибки.** Следуй контракту канала: если ответ не подтверждает откат
  (`safeToRetryWithoutCanvasRead` не true), сначала перечитай холст, потом продолжай. Пойманные `try/catch` ошибки
  возвращай в `errors` — неполная секция не считается готовой. `node does not exist` внутри инстанса — проверь скрытие
  (`skipInvisibleInstanceChildren`) и замену поддерева (свап/детач), заново найди узлы от стабильного родителя;
  сохранённые id восстановления не гарантируют. Смена варианта вложенного инстанса **не сбрасывает** override
  заливки/обводки — чисти явно.
- **Только из кода.** Тексты и данные verbatim (опечатки сохраняй), цвета только токенами кода → стили/переменные,
  никогда «с глаз» по скриншоту. Хардкод допустим осознанно (бренд-плейсхолдер) и с пометкой в отчёте.
- **Клон-инкремент.** Второй экран того же сервиса и состояния — от клона базы; скрытые вложенные ряды инстанса могут
  выпадать из обхода клона — прячь после правок текста, не до.
- **Пиксельный слепок** (`generate_figma_design`) — референс раскладки и фолбэк для картинок, не результат: не на
  компонентах кита, токены подобраны по значению, шрифты могут приехать недоступными. Доступность захвата из вкладки
  превью зависит от среды — проверь, не предполагай.

## Самопроверка и отчёт переноса

Главная проверка — **сверка результата с кодом, по каждому итоговому состоянию и после всех правок**: видимые
тексты и числа, картинки, выбранные состояния контролов, границы контейнеров (охватывают контент, без пересечений и
обрезки), скриншот при зафиксированном вьюпорте. Неперенесённое и непроверенное перечисляется явно как
`unresolved` — это не «нет пары». Тест редактируемости на копии: удлинить заголовок, добавить строку, сменить
состояние контрола — макет должен пережить без ремонта слоёв.

Описательные метрики одним версионированным обходом: **instance-share** (инстансы кита верхнего уровня, локальные
холдеры и содержимое слотов раскрываются как своё / все собственные рисующие узлы независимо от типа) — чувствительна к
формуле, проценты сравнимы только внутри одного обхода; цвета и геометрия через стили/переменные — **раздельно**;
число вызовов / упавших / фикс-итераций. Раунд-трип с исходным макетом — дополнительная ось.
Расхождения — классами: **промах сборки** (чинить) · **unresolved** (способ не найден / проверка не завершена) ·
**код ≠ макет** (честно: макет′ повторяет код) · **нет кит-пары** (после проверки вложенного) · **эквивалент**.
Отчёт переноса — таблица этих классов + карта имён экрана (hit / hit-override / miss) + новые грабли кита в паспорт.
Override текста и свапа — нормальная работа дизайнера, не штраф; штраф — ручная геометрия/заливка там, где у кита
есть свойство, и детач.
